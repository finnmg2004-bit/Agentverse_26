## 2. Project Summary: "Nudge"
A quadruped robot assistance dog (**Unitree Go2**) for **deaf, blind, and deafblind owners**, living in a furnished house (the **nerv-world "house"** scene, ground floor).
1. Listens continuously through simulated stereo ears (left/right microphones) and classifies household sounds locally via **YAMNet** (target: the full sound registry below; currently implemented: `doorbell`, `knock`, `smoke_alarm`, `kettle`, `oven_timer`).
2. Finds the owner inside the house using room-to-room doorway navigation, 2D LiDAR rangefinders for obstacle avoidance, and a local **YOLO nano** person detector on the head RGB-D camera.
3. Alerts the owner by physical contact (**nudge**) + **multimodal alert outputs** (haptic handle, coloured LED, on-robot screen, spoken message — see 2.2).
4. Guides the owner to the sound source (e.g. Front Door, Kitchen) or evacuates them out the **Back Door** (living-room garden door, west side) in an emergency.

### 2.1 Sound Registry & Response Tiers (agreed design — registry + kettle + oven timer implemented; per-tier haptic patterns and tier pre-emption not yet)
Modelled on what real hearing dogs are trained to alert to. Sounds are grouped by **what Nudge does**, not one rule per sound, so adding a sound is a data change (a registry entry in `sim/house_layout.py` + a YAMNet/AudioSet class mapping), and pre-emption is by **priority tier**, not a hardcoded `smoke_alarm` check.

| Tier | Sounds | Haptic | LED | Nudge's response |
|---|---|---|---|---|
| **1. Emergency** (highest priority) | Smoke / fire / CO alarm, glass breaking | `continuous` | Red | Pre-empt everything, find owner, guide them **out** (`back_exit_outside`) |
| **2. Needs action** | Kettle boiling/whistling, oven/microwave timer, baby crying, tap left running | `2 pulses` | Amber | Find owner, guide them **to the source** |
| **3. Someone wants you** | Doorbell, knock, phone ringing, alarm clock | `1 pulse` | Blue | Find owner, guide them to the door/phone (alarm clock: wake-up nudge only) |

- One haptic pattern **per tier** (not per sound): a deafblind owner can't easily learn a dozen codes; being guided to the source tells them *which* sound it was.
- Audio clips: the current `assets/audio/*.wav` files are **synthesized placeholder tones** (generated by `sim/sensors.py`), not real recordings. Replace with real household recordings per registry entry.
- Kettle: YAMNet has no kettle class; the registry maps it to `Whistle` / `Steam whistle`, which barely fire on the synthesized clip (0.2), so detection comes from the spectral rule in `hearing.py` (tonality of the ~2.25 kHz whistle). YAMNet hears a loud whistle as "Alarm"/"Fire alarm" (0.85 next to the stove), so `hearing.py` caps YAMNet's smoke score at 0.5 while the kettle rule fires and the spectral smoke rule doesn't confirm (a real smoke alarm still pre-empts).
- **Implemented (Ricktho):** every `SOUND_SOURCES` entry in `sim/house_layout.py` now carries `tier`, `file`, `yamnet` (class names), `label` and `say` (default "Nudge says") next to `pos`, `room`, `target_landmark`, `alert_mode`, `level`; derived `SOUND_TIERS`, `DANGER_SOUNDS`, `ALERT_SOUNDS` (non-danger, highest tier first). `sim/sensors.py` loads/synthesizes a clip per entry, `hearing.py` scores every entry, the brain's `ALERT_SOUNDS`, `DEFAULT_SAY` and score defaults come from the registry. To add a sound: registry entry + clip (or generator) + spectral rule if YAMNet can't recognise the clip + a hotkey in `run_sim.py` + a scenario.

### 2.2 Target Users & Multimodal Alert Outputs (agreed design — not yet implemented)
Designing for deafblind (the hardest case) covers deaf and blind owners too. Every alert is **one event** `{sound, tier, room, action/message}` fanned out to all output channels; a per-owner **profile** (`deaf` / `blind` / `deafblind`) says which channels matter. For the demo video, **all channels are on at once**.

| Output | Primary audience | Example (kettle) |
|---|---|---|
| **Haptic handle** — hinged + telescopic rigid guide handle (`sim/guide_handle.py`, implemented), grip glows in the haptic code | Deafblind | 2 pulses |
| **Coloured alarm LED** — police-style light bar on the Go2's back (`sim/lightbar.py`, implemented) | Deaf | Amber, blinking in the tier pattern |
| **On-robot screen** (panel on the Go2's back, large high-contrast text) | Deaf / low vision | `KETTLE · Kitchen · Follow me` |
| **Speaker / spoken notification** (local TTS only, e.g. Piper or espeak-ng — TBD) | Blind | "The kettle is boiling in the kitchen. Take my handle." |
| **Guiding to the source** (exists) | Blind, deafblind | Leads owner to the kitchen |

- **Light bar** (`sim/lightbar.py`, added in `sim/world.py`): "Police Lights" by KIDosn (Sketchfab, **CC BY 4.0**, credited in README.md), split by `pixi run prepare-lightbar` into housing + `red` / `center` / `blue` lens meshes in `assets/lightbar/` (committed). Each lens has its own material plus a translucent glow shell, so `LightBar.update(model, t, alert_mode)` (called from `locomotion.py`) sets colour + emission per step; a spotlight on the bar tints the floor. **Two jobs:** the **red + blue ends = danger only** (emergency: red end then blue end, back and forth, police double strobe, floor wash in the same colour; otherwise dark); the **centre lens = information** — which sound Nudge heard, as a colour + blink count matching the haptic code (`SOUND_INFO`): doorbell green ×1, knock yellow ×2, smoke alarm orange fast, task complete white steady, idle faint white. Centre colours avoid red/blue so they never read as danger. The sim infers the sound from `alert_mode` today; when the planned `alert` event lands, pass its `sound` to `LightBar.update(..., sound=...)` and add new sounds (kettle…) as `SOUND_INFO` entries. Visual only (group 2, no mass, no collisions), mounted on `base` at `(0.15, 0, 0.077)`, behind `head_cam`, ahead of the handle hinge.
- **Guide handle — rigid "hard leash" like a real guide-dog harness** (`sim/guide_handle.py`, added in `sim/world.py`; replaces the old yellow capsule and the floating `alert_halo` sphere). Built from primitives: a black U-shaped frame (outer tubes + sliding metal inner tubes + padded crossbar grip) on a hinge at the withers (harness saddle, base frame x = +0.05). **Stowed:** folded flat along the spine, pointing backwards. **Offered / guiding** (`guiding=True` or `alert_mode` in `1_pulse`/`2_pulse`/`continuous`): swings up ~43° toward the dog's RIGHT, then telescopes so the grip is at ~0.75 m hand height (`GRIP_BASE`); retracting reverses it. The grip glows white in the haptic pattern. Visual only (group 2, no mass/contacts), animated via `body_quat`/`geom_pos`/`geom_size`.
- **Owner while guiding** (`sim/locomotion.py`): like a real guide dog the robot walks on the owner's LEFT, so the owner is on the robot's RIGHT (`OWNER_OFFSET_BODY` = 0.50 m behind, 0.34 m right). The owner walks (≤ 0.4 m/s) to the handle, then is LOCKED to it (left hand on the grip, facing the robot's heading), so every stop or turn of the robot moves them. `nudge-brain/world_model.py` uses the same offset for the owner's known position while guiding. Optional idea, not built: a soft retractable leash (MuJoCo tendon) for a "follow me" mode.
- Colour is never the only signal (colour-blind owners): LED colour is always paired with a blink pattern and screen text.
- Screen: render text to an image and upload it as a MuJoCo texture on the panel; verify the MuJoCo 4.0 passive viewer supports live texture updates, otherwise mirror the screen in the dashboard.
- Real-world note: Nudge's own speech must not be re-detected by its ears as a new sound (not an issue in sim; mention in the technical summary).

### The One-Take Demo Story (<= 60s)
> **Proposed revision (one sound per tier):** replace the knock with a **kettle** (different room + different response than the doorbell): Doorbell (tier 3, owner moved mid-run) → Kettle (tier 2, guide owner to kitchen) → Smoke Alarm (tier 1, pre-empt and evacuate). If 60 s is too tight, drop the owner move or the kettle. Current story (nerv-world house) below until the team agrees.

1. Owner starts in the **Living Room**; robot starts in the **Entry hall**, facing north, a few metres inside the front door.
2. **Doorbell rings** (`[B]` key) at the front door. Robot hears & localizes it, plans to find the owner in the Living Room (route: entry → dining archway → living-room archway).
3. **Unscripted Change #1**: While the robot is en route, a teammate presses `[O]` to move the owner to the **Guest bedroom**.
4. Robot arrives in the Living Room, scans with the camera (`look_around`), sees the owner is missing, re-plans to search the **Guest bedroom** (via `door_guest_living`), spots the owner with YOLO, approaches, delivers the `1 pulse` alert, and begins guiding the owner toward the Front Door (via `door_guest_entry`).
5. **Unscripted Change #2 (Critical Pre-emption)**: Teammate triggers the **Smoke Alarm** (`[M]` key, kitchen ceiling). The safety layer immediately pre-empts the doorbell task, triggers `continuous` emergency vibration, and guides the owner out the **Back Door** to `back_exit_outside`.
- Optional extra change: `[C]` drops a chair into `door_guest_living`, forcing a reroute through the entry hall.
- ⚠️ **Timing budget**: the house is much bigger than the old 10×8 m box. Start → living-room scan ≈ 11 m, → guest-room owner ≈ 7.5 m more, guest room → `back_exit_outside` ≈ 13 m at the 0.4 m/s guiding cap. Plan for ~0.8–1.0 m/s cruise when alone; the video only has to show the evacuation *starting* under pre-emption, not finishing.

### World implementation notes
- **Model**: `sim.world.build_nudge_model()` = upstream house + Go2, plus (via MjSpec) `head_cam`, hinged guide handle (`sim/guide_handle.py`), light bar (`sim/lightbar.py`), `owner_body` + `chair_body` (mocap), `beacon_*` spheres. Contacts are disabled (`mjDSBL_CONTACT`): Plan B is kinematic (`qpos` + `mj_forward`, never `mj_step`), so the nerv Go2's torque motors are never driven.
- **Cutaway** (default): house geoms entirely above the ground-floor rooms (upper storeys, roof) move to group 5, which MuJoCo doesn't render; the viewer also hides ceilings (group 1). Ceilings stay visible to the robot's camera — hiding them shows blue sky, which looks like the owner's teal jacket.
- **Static nav map** (`sim/nav_map.py`): every collidable house geom overlapping z ∈ [0.10, 0.55] m rasterized at 5 cm, cached in `assets/maps/nerv_house_nav.npz` (git-ignored, rebuilt automatically when the scene changes; `pixi run build-map`). Locomotion clamps the robot (radius 0.25 m) against its clearance field and slides along walls; the brain plans on a 10 cm copy (robot radius 0.30 m, clearance cost keeps routes centred). Owner and chair are NOT in the map — LiDAR handles them.
- **Sound**: each source has a `level` (smoke alarm 4.0, doorbell/knock 1.0); wall occlusion is 0.45× per wall, capped at 3 walls (sound leaks through archways). Hearing gates the smoke score on 3.1 kHz narrowband prominence, so a smoke alarm is detected anywhere in the house even while the doorbell rings next to the robot.
- **Beacons** are hidden from the robot camera while it renders (viewer still shows them).
- **Vision** keeps the first teal blob that has valid depth on ≥ 50 % of its pixels and projects inside the house (+2.5 m margin for the outside exits); sky through windows / the open front door is rejected.

### World rules (nerv-world)
- **Never edit `worlds/nerv-world/`** (it is someone else's repo; bump the submodule commit to update). In particular `build/house-go2.xml` is a generated artifact.
- Anything Nudge-specific (owner body, chair, sound beacons, sensor sites) is **added at load time** in `sim/world.py` / `sim/run_sim.py` via `MjSpec`, never written into the upstream XML.
- **Furniture meshes**: upstream keeps third-party furniture meshes out of git. On our checkout they are missing, so `sim/world.py` drops them and substitutes stand-ins: fridge/stove/sink → their existing collision box made visible; armchairs, coffee tables, 6 dining chairs → visible proxy boxes (`proxy_*` geoms). Camera, LiDAR and collisions all see the stand-ins. (Optional, upstream tooling: `python -m decor.fetch` etc. inside the submodule restores the real meshes; then no stand-ins are added.)
- **Geom groups are a shared contract**: `0` house visible, `1` ceilings, `2/3` robot visual/collision, `4` hidden house collision boxes, `5` reserved upstream — we use it for the cutaway's hidden upper storeys. Anything we add to the house uses group 0 (or 4 if invisible). **LiDAR / any `mj_ray` must use `sim.world.HOUSE_RAY_GROUPS` (`[1,1,0,0,1,1]`)** so beams ignore the robot itself but still hit hidden collision boxes. Never hide a geom with `rgba` alpha 0 — `mj_ray` skips it.
- The scene is big (~3.3k geoms, compiles in ~0.3 s). Only the **ground floor** is used; stairs/upper floors are out of bounds.

## 5. Hardware Abstraction & ZMQ Contracts

### Robot model facts (upstream `worlds/nerv-world/robots/go2/go2.xml`)
- Free-floating body `base` (freejoint = `qpos[0:7]`), 12 leg joints, keyframe `home` (base z 0.27 m).
- ⚠️ Actuators are **torque `<motor>`s** (explicit PD, zero model damping), *not* Menagerie position servos. Plan B never steps physics, so this only matters for Plan A / dynamic simulation: never write joint angles into `data.ctrl`; `sim.world.StandingPD` (`tau = kp(q* − q) − kd·q̇`, kp 40, kd 1) holds a pose stably.
- The upstream model also ships a `head_front` camera (fovy 95°); Nudge adds and uses its own `head_cam` (below).
- Robot geoms are in groups 2/3 (see LiDAR rule above).

### Locomotion Interface (`sim/locomotion.py`)
The brain NEVER sends raw joint torques. It only sends body-frame velocity commands:
- `cmd_vel = (vx, vy, wz)` where `vx` is forward (m/s), `vy` is left (m/s), `wz` is yaw rate (rad/s).
- **Plan B (Default / Kinematic Base)**: Directly integrates `(vx, vy, wz)` on the Go2 freejoint (`qpos[0:7]`), clamped against the static nav-map clearance field (walls + furniture, slides along them) plus chair/owner circle push-out, with leg joints in the `"home"` pose plus a sinusoidal trot proportional to speed (written to `qpos`; `mj_forward` only).
- **Plan A (Optional Policy)**: Feeds `(vx, vy, wz)` to a MuJoCo Playground ONNX/JAX policy at 50 Hz (must match the explicit-PD torque convention above).
- **Owner Guiding Physics (`guiding: bool`)**: When `guiding=True` and the robot is within `1.4 m` of the owner, the owner smoothly follows a handle offset `0.55 m` behind/beside the robot at up to `0.4 m/s`.

## 6. Agent Tools & Safety Layer Rules
- **Agent Model**: Local Gemma 4 E2B via local Ollama HTTP API (`http://127.0.0.1:11434`, model `gemma4:e2b` / `gemma3:4b` with automatic deterministic tool-policy fallback if the answer takes longer than `NUDGE_WATCHDOG_S` (default **4.0 s**; measured ~0.4–0.6 s on an RTX 5050 laptop with spikes to ~3 s) or Ollama is offline). Setup: install Ollama (`winget install Ollama.Ollama`), then `pixi run fetch-models`. Wakes ONLY on discrete events: `new_sound`, `arrived_in_room`, `owner_seen`, `owner_not_found`, `owner_alerted`, `owner_no_response`, `handle_taken`, `path_blocked`, `timeout`.
- **How the LLM decides (`agent.py`)**: on each event `build_menu()` turns live perception into a lettered menu of LEGAL options with their facts (room probabilities + walking distance, exits with walk length + distance from the fire, nudge attempts, ...). Gemma answers through an Ollama JSON schema that only allows the menu's letters + a short reason (+ `call_emergency_services` in a fire), so it cannot produce an invalid call and answers in ~15 tokens (~1.5 s on an MX450, faster on bigger GPUs). Safety decides what is on the menu; the LLM decides which option. Single-option events are executed instantly (`only option`). Every decision records what the rules would have done; the dashboard flags LLM overrides with `*`. The LLM also decides in emergencies (exit choice, re-nudge vs lead out, calling emergency services); the pre-emption itself stays plain code.
- **Perception the agent uses** (all brain-side, no ground truth): `owner_belief.py` (Bayes filter P(owner in room): camera positive + negative evidence, owner-walks-around model), `sound_localizer.py` (sound position from ear ILD/ITD direction + loudness, accumulated over robot poses on a 0.5 m grid), `evacuation.py` (fire position from hearing; scores every exit by walk length + fire proximity; hazard doorways of the fire room are never used while leading the owner; exits LiDAR saw blocked are excluded).
- **Owner message + GUI reasoning**: when `alert_owner` is on the menu, Gemma also writes `say`, the short plain-words message Nudge shows/speaks to the owner when it nudges them (control GUI "Nudge says"; `DEFAULT_SAY` per sound otherwise; for the planned screen/speech outputs). Every decision is recorded in `agent.decisions` (event, source, choice, Gemma's reason or a plain-English rule explanation, latency, what the rules would have done, rejections/watchdog notes, raw reply, owner message) and published on the `brain` topic for the control GUI's reasoning panel. `NUDGE_LLM_EVENTS=new_sound,owner_not_found` (comma list) limits which events consult Gemma; default: every event.
- **Agent Tools**:
  - `get_state() -> dict`
  - `go_to_room(room: str)` — `room` ∈ `house_layout.nudge_rooms()`
  - `look_around()`
  - `alert_owner(sound: str, place: str)`
  - `offer_handle()`
  - `guide_owner_to(target: str)` — `target` ∈ `house_layout.LANDMARKS`
  - `investigate_sound()`
- **Plain-Code Safety Layer (`nudge-brain/safety.py`)**:
  1. **Smoke Alarm Pre-emption**: If `smoke_alarm` is detected with confidence >= 0.6, immediately interrupt any current plan, find owner, set `continuous` alert, and lead the owner out by the safest exit (`evacuation.py`: one of `EXIT_TARGETS` — `front_door_outside`, `back_exit_outside`, `terrace_outside`; `SMOKE_EVACUATION_TARGET` is only the default). Escalation: emergency services are called (simulated) by the LLM, or by plain code if the owner is still not found 40 s into the alarm. *(Planned: generalize to tier-based pre-emption — a higher-priority tier always interrupts a lower one; see 2.1.)*
  2. **LLM Watchdog**: If the LLM takes longer than `NUDGE_WATCHDOG_S` (default 4.0 s) to answer after an event, deterministic fallback rules take over immediately (logged as `watchdog` in the GUI).
  3. **Proximity Speed Cap**: Clamp speed <= 0.4 m/s whenever within 1.0 m of the owner.

### 6.2 LLM reasoning roadmap: reflex layer + thinking layer (ideas, agreed direction, not yet built)
**Principle:** use the LLM to reason about what a sound *means in context*; keep it out of anything that has to happen instantly.
- **Reflex layer (ordinary code, milliseconds):** a danger sound triggers the danger routine immediately; also obstacle stops, the stale-command watchdog that stops the robot, and the walking policy. The LLM can't override any of it, and nothing the person tells the robot can downgrade a smoke alarm. *(Today: `safety.py`, the sim's 0.6 s command timeout, LiDAR stops.)*
- **Thinking layer (local LLM, 1–3 s, only when something happens):** anything that needs judgement. It reads a short summary of the situation, picks **one action from a fixed list**, and gives a one-line reason shown on screen. *(Today: on each event Gemma picks one lettered option from a menu of legal actions built from live perception, gives a short reason, and writes the owner message when nudging is an option; JSON-schema constrained; see section 6.)*

Reasoning to add, best demo value first:
1. **"Is the sound real, and where is it?"** The LLM combines the classifier's top guesses, the stereo bearing, the floor plan and recent events. Demo: a doorbell plays on the **TV**; the bearing points at the TV (which is on) and the front door is the other way, so the robot keeps listening instead of fetching the person. Then the real doorbell rings in the hallway and it acts. A sound classifier alone can't make that call, which makes this the clearest proof of reasoning grounded in perception. *(Needs: a TV sound source + "TV on" state in the sim, top-k classifier scores and bearing in the prompt, an "ignore / keep listening" action.)*
2. **Deciding what comes first and how to alert.** When two things happen at once (e.g. oven timer + doorbell), the LLM uses the person's state (on the sofa, asleep, in the bathroom) and the time of day to choose the order and the kind of alert: nudge and wait, persistent wake-up, or wait outside the bathroom door. It also writes the message shown on the robot's screen. **Keep messages short and plain: for many BSL users English is a second language.** *(Fits the sound tiers in 2.1.)*
3. **Personal rules in the person's own words.** They type e.g. "I'm expecting a parcel today" or "don't wake me for the oven timer after 11pm"; the LLM turns that into a **structured rule** that ordinary code enforces and the screen displays. Covers "learning on the fly", and stays safe because danger sounds are outside what any rule can change.
4. *(Optional)* **Visual check on arrival:** ask a small vision-language model "is there visible smoke?" / "is someone at the door?". It can only **add** information; it never cancels an alarm.

## 7. Keyboard Event Hotkeys in MuJoCo Viewer (`sim/run_sim.py`)
- **`B` or `1`**: Ring **Doorbell** (Entry hall, front door)
- **`K` or `2`**: **Knock** on Front Door (Entry hall)
- **`M` or `3`**: Trigger **Smoke Alarm** (Kitchen ceiling — Emergency)
- **`T` or `8`**: **Oven timer** beeping on the kitchen stove (tier 2, like the kettle; Nudge guides the owner to the stove).
- **`J` or `7`**: **Kettle** whistling on the kitchen stove (tier 2: 2 pulses, Nudge guides the owner to the kettle). During another mission for a different place it is deferred and alerted afterwards.
- **`O` or `4`**: Cycle **Owner** room (`OWNER_ROOM_CYCLE`: `living_room` -> `guest` -> `dining` -> `family_room`)
- **`C` or `5`**: Toggle **Chair** obstacle in `door_guest_living` (-7.6, 0.6)
- **`X`**: Silence all active sounds
- **`W`**: Toggle owner **wandering** (on by default; `--owner-static` starts with it off). The owner (`sim/owner_behavior.py`) walks between `OWNER_SPOTS` rooms on their own every ~35–90 s (never in the first 45 s), pauses at doorways, may miss the first nudge (70 % noticed), taps the handle to acknowledge, varies pace on the handle and occasionally lets go. `--owner-seed N` makes it reproducible.
- **`E`**: Chair falls into the **back exit** (`CHAIR_EXIT_POS`) — LiDAR marks `exit_back` blocked and the evacuation re-chooses an exit. Press again to stow.
- **`R`**: **Reset** the scene (robot to the entry-hall start pose, owner to living room, chair stowed, sounds off). Bumps the `episode` counter in `state`; the brain sees the change and drops its mission, plan, alerts and owner belief. Also works from the dashboard window.
- **`N` or `6`**: Cycle **background noise** for hearing robustness tests: `quiet` → `fan` → `tv` → `vacuum` → `party` (start with `--noise NAME`)
- **`V`**: Cycle **viewer camera**: `top` dollhouse view → `follow` (chase the robot) → `dog` (the head RGB-D camera = exactly what YOLO sees) (start with `--view NAME`)
- **Scenario end condition** (sim ground truth): owner held ≥1 s within 1.4 m of the sound's target (front door for doorbell/knock, the stove for the kettle) ends it (sound stops, `SCENARIO COMPLETE`; 1.4 m because the owner lags ~1.2 m behind the handle); owner at the back door or outside ends the smoke alarm (all alarms clear). Unresolved after 120 s → `SCENARIO FAILED`.
- Prefer **letters** in the MuJoCo window: its built-in number-key shortcuts may also toggle geom-group visibility.

**Mission complete indicator**: when the owner has been delivered, the brain reports `mission_status: "complete"`; the MuJoCo viewer shows a `MISSION COMPLETE` overlay (with sound, target and sim-time duration), the robot's halo turns steady green, and the dashboard shows a green banner. It stays until the next mission starts or `R` is pressed.

**Robot outputs ("Nudge says" screen, LEDs, speech)** (Sean, `sim/robot_screen.py`, `sim/robot_voice.py`): the sim subscribes to the brain's `brain` status and shows `mission.say` as a floating label above the robot and a bottom-left viewer overlay, logs `[sim] NUDGE SAYS: ...` on every change, and adds `nudge_says` to `state`. Two flank screens on the trunk take the alert-tier colour from the light bar palette (doorbell green, knock yellow, smoke red/orange flashing, complete white, idle dark). Speech: `NUDGE_SPEECH=1` speaks each new message once via Teo's `speech.tts.speak` (smoke alarm with `interrupt=True`), always prefixed "Nudge says: ..." so the voice input ignores the robot's own speech; without a TTS backend it logs `[voice] would say: ...`.

**Note:** in the MuJoCo viewer every letter and the digits 0-5 are also MuJoCo display shortcuts (e.g. `2` hides geom group 2 = the robot, `X` turns textures off, `K` hides the skybox), so our hotkeys also toggle those. Use the control GUI (7.1) or the OpenCV dashboard window to trigger events cleanly.

### 10.1 Option A — ideal: an agent that builds new behaviour and learns its own house
1. **The robot maps the house itself.** At first start it **explores** (frontier exploration: drive to the nearest unexplored edge) and builds its own map: LiDAR -> occupancy grid; head camera + YOLO -> **object memory** (bed, sofa, TV, fridge, chair… with positions); **room names** inferred from objects (bed -> bedroom, stove/fridge -> kitchen, sofa + TV -> living room; Gemma suggests, the owner can confirm "this is the kitchen"). 2. **Live updates.** While working it keeps the map current: new obstacles (chair in a doorway -> re-plan), moved objects ("the chair moved from the dining room to the guest-room door"), owner last seen where/when. The GUI shows **the robot's own map**. `sim/house_layout.py` stays only for tests / the judge's ground truth; the brain never reads it. (Honest note for the summary: the robot's pose comes from the sim; a real robot would use SLAM.)
3. **Primitive actions** (plain code, safe; Gemma composes them): move `go_to(place|object|owner)`, `turn`, `scan_room`, `approach`, `wait(s)`, `wait_until(cond)`; perceive `find(person|object)`, `where_is_owner()`, `what_did_i_hear()`, `is_owner_moving()`, `time_now()`; interact `nudge()`, `vibrate(pattern)`, `say(text)` (Piper), `show(text)` (screen), `lights(pattern)`, `offer_handle()`, `guide(to)`, `ask_owner(question)` (voice/GUI answer), `call_emergency()`; memory `remember(fact)`, `recall(fact)`.
4. **Teach (Gemma, schema-constrained):** sentence -> a small **task program**: trigger + steps (+ simple `if` on perception, `on_fail`). The JSON schema only allows known primitives, places and objects (from the robot's own map). Ambiguous -> `ask_owner` ("Which bed?"). Confirmed back on screen + voice, stored in a task file, listed/edited/deleted in the GUI.
5. **Run (plain code):** trigger watcher (time / sound / owner idle / event such as "owner entered room") -> program runner executes the steps; Gemma is woken only for decisions and failures (re-plan), not every step.
6. **Safety (plain code, always on):** tier-1 danger pre-empts any task; geofence (avoid areas, stairs, upper floors); speed caps; every program validated before running (known primitives only, max duration, no endless loops, reachable on the map); the watchdog fallback stays.
7. **Switch:** `NUDGE_AGENT=planner|menu`; today's menu agent stays as the fallback.
